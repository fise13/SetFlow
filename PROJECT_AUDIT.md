# SetFlow — аудит проекта: проблемы и улучшения

Документ описывает текущее состояние приложения SetFlow (iOS/watchOS): выявленные проблемы, технический долг, идеи по улучшению UI/UX и кода.

---

## 1. Кратко о проекте

- **Назначение:** приложение для тренеров и атлетов: тренер создаёт планы и назначает тренировки, атлет выполняет тренировки в реальном времени (подходы, таймер отдыха, лог).
- **Стек:** Swift/SwiftUI, Firebase Auth, Firestore, WatchConnectivity, локальные уведомления.
- **Роли:** Coach, Athlete. Регистрация → выбор роли → для Athlete — ввод инвайт-кода от тренера.

---

## 2. Критичные и важные проблемы

### 2.1 Auth (вход и регистрация)

| Проблема | Где | Описание |
|----------|-----|----------|
| **Forgot password не реализован** | `AuthViews.swift` | Кнопка «Forgot password?» есть, обработчик пустой (TODO). Пользователь не может восстановить пароль. |
| **Sign in with Apple не реализован** | `AuthViews.swift` | Показывается сообщение «Sign in with Apple is not configured yet». Нет кода и настройки в Apple Developer. |
| **Ошибка Firebase «credential malformed or expired»** | — | Возможные причины: истёкший/неверный credential (например, при связке анонимного аккаунта с email), неверный формат. Нужна явная обработка ошибок Auth с понятными сообщениями пользователю. |
| **Нет валидации/ограничения пароля при Sign Up** | `AuthViews.swift` | Есть проверка «min 6 characters», но нет проверки сложности (буквы, цифры, спецсимволы) и нет подсказок. |

**Рекомендации:**  
- Реализовать восстановление пароля через `AuthService.resetPassword(email:)` и экран/алерт «Введите email для сброса».  
- Либо включить Sign in with Apple (конфиг в Xcode + Capabilities + обработка в коде), либо убрать кнопку из UI.  
- Добавить маппинг кодов ошибок Firebase Auth в человекочитаемые строки (в т.ч. «credential malformed or expired»).

### 2.2 Профили и настройки (Athlete / Coach)

| Проблема | Где | Описание |
|----------|-----|----------|

**Рекомендации:**  
- Либо реализовать экраны Units/Notifications (UserDefaults или Firestore), либо временно скрыть или заменить на «Coming soon».  
- «Manage subscription»: либо убрать, либо заменить на «О подписке» / «Тарифы» с заглушкой.  
- Добавить экран «Редактировать профиль» (имя, при необходимости смена email через Firebase).

- В критичных местах (создание плана, сохранение лога, redeem кода) показывать алерт/тост с текстом ошибки вместо тихого fail.

### 2.4 Athlete

| Проблема | Где | Описание |
|----------|-----|----------|

### 2.5 Watch

| Проблема | Где | Описание |
|----------|-----|----------|
| **Таймер отдыха не работает** | `WatchViews.swift` — `WatchRestTimerView` | В `onAppear` только «Simple animation placeholder instead of real timer». Секунды не тикают. |
| **Навигация через NavigationLink** | Watch | После «Done» / «Skip» переход по стеку; для сценария «тренировка → отдых → следующее упражнение» лучше одна модель состояния и обновление одного экрана. |

**Рекомендации:**  
- Реализовать таймер на Watch (например, `Timer.publish` или обновление `@State` раз в секунду с учётом фона).  
- Рассмотреть один «Live» экран с состоянием (exerciseIndex, set, restRemaining) вместо цепочки NavigationLink.

### 2.6 Общие технические проблемы

| Проблема | Описание |
|----------|----------|
| **Нет unit/UI тестов** | В проекте нет *Test* таргетов. Критичные сценарии (auth, создание плана, сохранение лога) не покрыты. |
| **ContentView + Persistence (Core Data)** | Остатки шаблона Xcode: `ContentView`, `Persistence.swift`, модель `Item`. В основном потоке используется `SetFlowApp` → `RootView`. Риск путаницы и лишнего кода. |
| **Нет Firestore rules в репозитории** | В корне нет `firestore.rules`. Правила безопасности должны быть в репозитории и деплоиться вместе с проектом. |
| **Дублирование типографики** | В коде используется и `AppTypography`, и `AppTheme.Typography` (через typealias). Для единообразия лучше один вход (например, только `AppTypography`). |
| **pendingDisplayName не @Published** | В `AppState` поле `pendingDisplayName` не помечено `@Published`, поэтому изменения не триггерят обновление UI при биндингах (если бы использовались). Сейчас используется только для чтения после перехода на RoleSelection — не критично, но для консистентности можно сделать @Published или убрать после использования. |

## 3. UI/UX

### 3.1 Консистентность

- **Цвета:** тёмная тема на Welcome/Sign In (градиенты, белый текст), светлые экраны в приложении (Coach/Athlete). Резкий контраст при переходе «логин → дом» — можно смягчить общим акцентом и одним набором фонов.
- **Кнопки:** используются и `PrimaryButton`, и кастомные кнопки с `LoadingButtonLabel`. Имеет смысл свести к 2–3 типам (primary, secondary, text) и везде использовать компоненты из дизайн-системы.
- **Пустые состояния:** на Athlete уже есть («No workout today», «No workouts yet»). На Coach в списке атлетов/планов при пустом списке стоит добавить такие же карточки с иконкой и текстом.

### 3.2 Навигация и обратная связь

- После сохранения лога в Summary — переход «Back to home» и сброс стека; убедиться, что таб «Workout» не остаётся в «промежуточном» состоянии (например, снова показывается деталь сегодняшней тренировки, а не пустой экран).
- Критичные действия (создание плана, отправка атлету, сохранение лога) стоит сопровождать коротким хаптиком и, при желании, тостом «Сохранено» / «Отправлено».

### 3.3 Доступность и локализация

- **Accessibility:** нет `accessibilityLabel` / `accessibilityHint` на кнопках и карточках. Сложные экраны (Live Workout, календарь) будут слабо понятны VoiceOver.
- **Локализация:** все строки захардкожены на английском; нет `LocalizedStringKey` / `NSLocalizedString` и `.strings` файлов. Для выхода на другие языки нужен план локализации.

**Рекомендации:**  
- Добавить метки и подсказки для основных кнопок и состояний (например, «Сегодняшняя тренировка», «Начать тренировку»).  
- Вынести строки в `Localizable.strings` и использовать ключи в коде.

## 4. Улучшения по разделам

### 4.1 Auth

- Реализовать Forgot password (экран или алерт с полем email + вызов `resetPassword`).
- Реализовать или убрать Sign in with Apple.
- Улучшить сообщения об ошибках (маппинг Firebase Auth errors).
- Опционально: проверка надёжности пароля при регистрации и подсказки.

### 4.2 Design system

- Добавить недостающие стили, если нужны (например, `title3`), чтобы не подменять их `title2` в разных местах.
- Зафиксировать использование только `AppColors` / `AppTypography` / `AppSpacing` (без прямого обращения к `AppTheme.Colors` в UI).
- Опционально: тёмная тема для всего приложения через `@Environment(\.colorScheme)` и отдельные токены для light/dark.

### 4.3 Coach

- Заменить placeholder в блоке Progress у атлета на реальные данные из логов (объём, количество тренировок, простой график).
- Добавить пустые состояния для списков (нет атлетов, нет планов).
- Обработка ошибок при создании/обновлении плана и при отправке «update» атлету.

### 4.4 Athlete

- Сделать календарь «This week» интерактивным (переход к тренировке на выбранный день).
- В Summary при ошибке сохранения — кнопка «Повторить» и/или локальное сохранение с последующей синхронизацией.
- Настройки: экраны Units (kg/lb) и Notifications (вкл/выкл, время напоминания) или явные заглушки.

### 4.5 Watch

- Реальный таймер отдыха в `WatchRestTimerView`.
- Упростить навигацию Live workout (одно состояние вместо цепочки экранов), если нужно.

### 4.6 Инфраструктура

- Добавить в репозиторий `firestore.rules` (и, при необходимости, `firestore.indexes.json`) и описать в README, как деплоить.
- Удалить или явно пометить неиспользуемый код: `ContentView`, Core Data (`Persistence`, `Item`), если они не используются.
- Добавить таргет тестов и покрыть ключевые сервисы (InviteCodeService, AuthService, создание пользователя) и критические пути UI (например, через XCUITest или SwiftUI Preview + моки).

## 6. Итог

Проект уже имеет рабочий сценарий: регистрация, выбор роли, инвайт-код, планы тренера, живая тренировка и лог у атлета, Watch и уведомления. Основные зоны роста:

- **Довести до конца auth:** восстановление пароля, понятные ошибки, решение по Sign in with Apple.
- **Убрать заглушки:** Progress у Coach, таймер на Watch, кнопки «Manage subscription» и неработающие настройки (или заменить на явные «скоро»).
- **Усилить надёжность:** обработка ошибок, офлайн/retry для лога, Firestore rules в репозитории.
- **Упорядочить код:** один источник правды для типографики/цветов, при необходимости — вынос строк и доступности.

Этот файл можно использовать как живой чеклист: отмечать выполненные пункты и дополнять новыми по мере развития приложения.
